# Coding convention

- Imports are added automatically so you don't need to import stuff, also it will crash if you include imports inside of `client/`
- In every file, you can export one thing, and that one thing should have the same name as the file
- don't use `export default`
    - simply because that is how we have done it so far
    - exception: web components use matching hyphenated `.html` and `.js` filenames; their JavaScript exports `export default async ({ html }) => { ... }`, with template IDs available on `html`
    - Custom components export an options object: `export default { fields: () => ({ ... }), onFirstDomAdd: html => { ... } }`. The synchronous `fields()` factory runs once per instance in its constructor; its result is available as `html.fields` and as direct properties when the name does not already exist on the element. Access template elements in DOM hooks after setup. Object-style `methods`, `state`, page callbacks, and hover/click callback maps receive their component host as their first argument; `state` also receives `setState` second.
- Native prototype enhancements can be classes extending `NativeEnhancer`; call `super(Array.prototype)` or the appropriate target prototype, then declare methods, getters, and setters directly on the class. Pass `allowOverride` and `excludedMembers` arrays in the optional second argument to `super()`. Every copied member that already exists anywhere on the target prototype chain must be listed in `allowOverride`; unapproved collisions fail before members are installed. Override entries must match real enhancer members and existing target members. Copied members execute with the native object as `this`, so they cannot use private class fields or `super`.
- Frontend and backend JavaScript use `if condition {`, `else if condition {`, `switch value {`, and parenthesis-free loops such as `for let i = 0; i < count; i++ {`, `for const item of items {`, `for const key in object {`, and `for await const chunk of stream {`. Keep each control-flow header on one line, ending with its opening `{` (optionally followed by a line comment), so the transpiler can restore standard JavaScript syntax. Shared JavaScript and files with `// disable-transpiling` use normal parentheses.
- `scripts/lint.sh` uses `dev/LintProject.js` to lint custom control-flow and case blocks as standard JavaScript in memory, then restores project syntax before writing fixes. It uses installed tools and caches unchanged source files and complete check results under `.cache/lint/`, skipping tool startup on unchanged runs. Source/configuration changes invalidate the relevant caches; cached errors are still displayed and return a nonzero exit status. Use `node dev/ConvertControlFlowSyntax.js --check` to report standard control-flow headers that need conversion without changing files.
- Switch blocks can use `case value {` and `default {`; the transpiler adds the colon and closing `break`.
- Run `node --test dev/tests/ControlFlowSyntaxChecks.js` to check control-flow conversion, loop errors, parameter detection, execution, and ESLint round trips.
- ´./scripts/lint.sh´ will take care of most of the coding convention

- Page modules export `const page = { persistOnClose: true }`. Startup registers each `-page` name with `Page.init(tag, module.page)` after defining the custom element. Persistence is an explicit boolean known before setup. An optional `layout` names a custom element that receives the page as a child and owns its positioning. Layout instances are created through the shared `Layout` registry; after the layout is open and ready, code can use a dynamically derived alias such as `Layout.pretty` for `pretty-layout`; aliases use the first hyphen-separated name segment. Return instance callbacks `onPageOpen`, `onPageClose`, and `onToggle` at the top level of the default setup result; they may close over instance state and may be asynchronous. Navigate with `Page.open("my-page")` or `on-click-open-page="my-page"`.
- The top-level `onFirstDomAdd(html)` component hook runs once when the instance first connects, before `onDomAdd(html)`. `onDomAdd(html)` runs after setup on every DOM connection; `onDomRemove(html)` runs when the element is removed from the DOM, after pending addition callbacks complete. All three receive the host element and may be asynchronous; callbacks can omit the argument. Keep one-time DOM wiring in `onFirstDomAdd`, repeated subscription setup in `onDomAdd`, and cleanup in `onDomRemove`. Page lifecycle callbacks are `onPageOpen` and `onPageClose` in the returned options.

- Ordinary DOM removal preserves contents, state, and handlers. `Page.pages[tag]` holds page metadata and the cached or active element. Registration creates detached persistent elements and keeps nonpersistent `page` fields null until opening. `Page.open()` uses persistence to create or reuse an element, waits for `whenReady()` to read instance callbacks, then invokes `onPageOpen()` and `onToggle("open")`. `Page.close()` invokes `onPageClose()` and `onToggle("close")`, removes the element, clears nonpersistent references, and resets `activeTag`. Both methods return no element. Opening the active page or closing without an active page throws. Setup errors propagate without cleanup. DOM hooks remain independent of navigation callbacks.
